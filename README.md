# 小米智能存储下载中心

插件版本 **1.1.2**。内置 **qBittorrent 5.2.4（libtorrent 2.0.15）**，HTTP／HTTPS／FTP／SFTP 直链保留 aria2。两个核心以所属普通用户独立运行，不依赖 Docker；现有插件界面、目录树、文件选择、Tracker 订阅与安全删除逻辑保留。

## 1.1.2 更新

- 设置页新增局域网接口卡片：显示实际监听状态、分配端口及不含密码的地址。qBittorrent 展示的是 Openlist 兼容接口，并非原生 WebUI 或 BT 入站端口。
- aria2 可选开放 HTTP JSON-RPC 局域网接口，仍使用现有 RPC 密钥；核心原生接口保持回环监听。新监听由插件进程管理，无额外 root 服务，限制明确配置的私网来源，支持 AriaNg HTTP 的跨域预检，不支持 WebSocket。HTTPS 网页需 HTTPS 反向代理。不要把管理接口转发到公网。
- 新增接口密钥卡片：默认不读取密钥，手动显示后可隐藏清空。先停止下载服务，再保存密钥并启动；运行中的核心、启动操作或核心更新会阻止修改。两项留空各自保持不变，写入失败尝试恢复旧值，文件权限 0600。不会自动修改 Openlist、AriaNg 等外部客户端配置。
- 统一两个内核更新卡片的 Mihomo 代理说明；电脑和手机、浅色和深色布局沿用统一样式。

aria2 局域网监听配置保存在当前插件 `var/aria2-lan.json`，格式与下面的 `openlist-lan.json` 相同。填入实际 NAS 私网 IP 和允许的局域网／Docker 网段后重启下载服务；默认未配置则不开放。监听端口沿用 `var/rpc.port` 分配的 19300–19399，不要硬编码其他用户端口。密钥保存在 `var/rpc.secret`，不要提交到仓库。

AriaNg 接入时填写 `http://<NAS局域网IP>:<RPC端口>/jsonrpc` 和插件 RPC 密钥，下载目录填写 NAS 当前用户空间的真实绝对路径；容器内的 `/opt/aria2/Download` 别名无效。直接 RPC 可操作核心内其他客户端的任务，不经过插件界面的目录/任务过滤，只应给可信用户密钥。外部任务不会自动成为插件自身登记的任务。Openlist 的临时目录需要单独适配，本次不会自动切换其 aria2 连接。

## 1.1.0 双核心更新

- 新 BT／磁链交给 qBittorrent；原 aria2 BT 任务保留原核心直至处理完毕，不冒险自动迁移未完成文件。任务列表、批量按钮和历史记录同时管理两类任务。
- 新增 IPv6、DHT、PEX、本地节点发现、UPnP／NAT-PMP、每任务及全局连接上限。qBittorrent 的 DHT 开关同时作用于已启用的 IPv4／IPv6，没有独立 IPv6 DHT 开关。首次切换 IPv6 与 UPnP 默认关闭；DHT、PEX、本地发现默认开启。
- BT 设置先保存，确认重启当前用户下载核心后生效；不重启 NAS。使用同一核心的 Openlist 下载也会短暂中断。服务停用后开机不会自动拉起。
- 修复任务按钮操作后等待下一轮刷新才更新的问题；普通状态查询不再重复全量扫描所有任务文件，单任务操作仅同步该任务。Tracker 订阅下载不再阻塞后台队列同步。
- 私有种子不追加用户配置的公共 Tracker。DHT／PEX 等私有种子限制由核心遵守。
- HTTP／BT 的并发及限速按每个核心分别生效，两个核心同时工作时合计可能达到两倍设置；Openlist 共用 qBittorrent 的限速和连接上限。
- 两个核心各有独立网页更新按钮，不能把 aria2 更新按钮当作 qBittorrent 更新按钮。

### Openlist 接入

设置页点击“显示 Openlist 连接信息”，复制专属 URL 到 Openlist 后台的离线下载 → qBittorrent URL。URL 内含密码，切勿公开。插件普通状态接口不会返回密码，隐藏连接信息时会清除页面输入框。

- 默认仅监听本机兼容端口（安装器从 19700–19799 分配），适用于 host 网络。bridge 容器可通过下述可选局域网监听连接，不要使用容器内的 127.0.0.1。
- 兼容层转换新版 qBittorrent 登录／创建任务响应和停止状态，仅开放 Openlist 所需接口；不提供核心设置修改和文件删除接口。
- 仅可查询、移除带 Openlist 标签且保存于当前用户空间的任务；插件自身记录和 Openlist 任务分开，不在下载中心列表混合显示或批量删除。
- 容器的 `/opt/openlist/data/temp/<任务目录>` 会转换为当前 NAS 用户的 `data/Download/<任务目录>`。Openlist 必须将这两个路径映射到同一实际目录。当前用户空间的同名绝对路径也可以直接使用；其他路径被拒绝。
- 若 Openlist 的临时目录映射不是上述约定，先调整映射，或将运行配置 `var/settings.json` 的 `openlistDirectory` 设置为对应的用户空间相对路径，再重启下载服务。不能填写其他用户路径。
- 不自动改变 Openlist 的现有 aria2 配置或将所有离线下载默认切换为 qBittorrent。新建离线任务时选择 qBittorrent。
- 共用核心意味着启动／停止服务与全局 BT 设置也影响 Openlist 任务；卸载插件后，该连接不再可用。

可选局域网监听：在当前插件 `var/openlist-lan.json` 写入以下配置，并重启该用户下载服务。地址须替换为 NAS 实际 IPv4 地址，允许网段须对应实际局域网及 Docker 网络；只接受 RFC1918 私网。接口同时保留本机监听、登录认证、来源网段检查和任务／路径限制，不开放核心原生管理 API。设置页显示的 Openlist URL 会采用配置的局域网地址。不要将该端口转发至公网；凭证经 HTTP 传输，只适合可信内网。

```json
{"address":"192.168.1.100","allowedNetworks":["192.168.1.0/24","172.18.0.0/16"]}
```

开机时局域网地址尚未就绪，会保留本机服务并重试监听，不影响下载核心启动。配置文件位于用户 `var` 中，普通插件升级会保留；NAS 地址或 Docker 网段变化后需相应更新。

## 功能

- HTTP / HTTPS / FTP / SFTP 直链；批量链接最多 20 条。
- BT v1 磁链、普通/混合 `.torrent` 种子（最大 4 MiB、导入时最多 2000 个文件）。纯 BT v2 暂不支持。
- 下载队列、搜索筛选、进度、速度、剩余时间估算、做种状态、暂停/继续、队首调整、失败重试。
- 种子导入时勾选文件；磁链获取元数据后暂停，再进入详情选择文件。
- 后台执行全部暂停/继续及历史清理，不使用阻塞整个页面的等待窗口。
- 删除单个任务时可勾选“同时删除已下载和未完成文件”，默认不勾选。清空历史仅移除记录。
- 并发数、连接数、上传/下载总限速、做种时间和分享率设置。
- Tracker 手动列表、最多 3 个 HTTP/HTTPS 订阅、一键更新、去重、每天自动更新（默认关闭）、应用到进行中的 BT 任务。
- 每用户独立进程、端口、密钥、配置和记录，不依赖 Docker、不复用 Openlist 自带核心、不需要额外 root 权限助手。

## 下载目录

创建任务时点击“下载到”，在居中弹窗中选择当前用户“我的文件”里的目录。支持树形展开/折叠、默认/最近目录定位，以及在树中输入名称并点击 ✓ 创建文件夹。点击“新建文件夹”或仅输入名称不会创建目录，点击 × 取消也不会创建。后端拒绝绝对路径、`..` 和符号链接，不能选择系统目录、其他用户文件区或共享给我的目录。

直链直接下载到所选目录，不创建编号子目录。BT / 磁链创建与资源名称对应的文件夹，避免重复嵌套同名层级；磁链先在插件私有目录获取元数据，校验后才开始写入用户目录。同名文件或文件夹会加 `(1)`、`(2)` 等后缀，保留已有内容。任务卡片显示实际位置。

删除文件按任务登记的目录和文件名定位，不比较 inode 或设备号。仍禁止越出当前用户空间、跟随符号链接或递归删除整个目录；未登记的文件与非空子目录保留。如果同名文件已被替换，也会按登记路径删除，请在删除前确认。文件删除失败仍移除任务记录并提示残留；任务必须先成功停止。删除文件不能撤销。

## 安装 / 更新 / 卸载

保留完整目录结构：`manage.sh`、`payload/`、`README.md` 和 `THIRD_PARTY_NOTICES.md`。统一入口：

```bash
bash manage.sh
# 或
bash manage.sh install
bash manage.sh uninstall
```

- NAS 本机：自动识别，以 root 运行安装器。下载服务始终以所选普通用户身份运行。
- WSL / Linux：自动通过 root SSH 连接，交互询问设备 IP；不写死 IP 或账户。
- 安装和卸载均扫描用户，支持单选、逗号多选或 `all`。只操作所选用户。

```bash
bash manage.sh install --ip 192.168.31.100 --users u123456789
bash manage.sh install --all-users
bash manage.sh install --list-users
bash manage.sh install --all-users --dry-run
bash manage.sh uninstall --users u123456789 --yes
```

本机执行时省略 `--ip`；远程非交互执行需要 SSH 密钥。安装前必须已初始化用户并正常挂载存储池。安装器要求 ARM64、Python 3.8+（含 sqlite3）、jq、runuser、flock、ss 和设备原有 plugincenter。

首次安装自动下载固定版本 **qBittorrent 5.2.4 / libtorrent 2.0.15** 与 **aria2 1.37.0 ARM64 静态构建**，核对固定 SHA-256 后提取核心。第三方构建来源见许可说明，校验失败不会安装。GitHub 网络受限时可预先下载指定 ZIP，再离线安装：

```bash
DOWNLOADCENTER_CORE_ARCHIVE=/你的路径/aria2-aarch64-linux-musl_static.zip \
DOWNLOADCENTER_QB_BINARY=/你的路径/aarch64-qbittorrent-nox \
bash manage.sh install
```

指定的 aria2 离线 ZIP 与 qBittorrent 离线可执行文件同样必须通过固定哈希校验，不接受随意替换的可执行文件。文件下载在执行安装的电脑/WSL或 NAS 本机进行，可按环境设置 `https_proxy`。

更新保留配置、队列和记录；原来停用的服务保持停用。卸载会停止所选用户服务，移除网页注册、用户专属定时项及程序，但不删除任何下载文件。配置和记录先备份到：

```text
/home/<用户>/plugin/.reserve/downloadcenter/<时间>-<进程号>/
```

备份可能含私密下载链接、种子和控制密钥，不应公开。其他用户仍在使用时保留共用图标。

## 启动与端口

- 安装和网页部署使用小米系统一致的完整目录 SHA-256 摘要；安装结束调用系统校验，避免重启时因摘要不一致被强制卸载。请勿直接修改已安装的 `src` 内容而不更新 `INFO.abstract`。
- 内置核心位于 `src/files/aria2c` 和 `src/files/qbittorrent-nox`；网页更新核心位于 `var/core/` 同名文件，优先使用并在重装时保留，不改动受校验的源码目录。
- RPC 控制接口仅监听本机，端口从 `19300–19399` 分配，每用户独立密钥；不要将 RPC 映射到公网。
- qBittorrent API 从 `19500–19599` 分配，仅监听 127.0.0.1。Openlist 兼容接口从 `19700–19799` 分配，默认仅本机，可按上文显式启用私网监听。两者均需要认证，不要向公网转发。原 aria2 BT 任务使用独立 `19600–19699` 端口，避免双核心冲突。
- qBittorrent BT TCP/UDP 端口从 `19400–19499` 分配，具体值安装结束显示，也保存在 `var/peer.port`。需要更好的入站连通性时，可自行转发该用户 BT 端口，不是网页/RPC 端口。
- 安装创建 `/etc/cron.d/downloadcenter-<用户>`，每分钟以普通用户检查下载服务。只在存储池已挂载且服务处于启用状态时启动。
- 手动停止服务后保持停止；重启后最多等待约一分钟恢复。运行中检测到存储池未挂载会停止核心。正常停机会保存队列；异常断电仍可能丢失最近约 15 秒的核心会话变化。
- 暂停任务在重启后保持暂停。已完成/失败记录独立保存在 SQLite，不依赖核心内存历史。

## UI

沿用现有插件的雾蓝灰背景、浅色卡片、电脑侧栏、手机标签页和左右滑动切页；显示插件版本号。手机跟随 Android / iOS 系统深色偏好，电脑客户端保持与现有插件一致的浅色方案。

目录选择和确认框都是网页内的居中圆角弹窗；无原生 select/confirm。弹窗打开时锁定背景滚动，二级弹窗遮蔽下层弹窗，动作按钮就地转圈。小窗口独立滚动到底，高分辨率不使用 CSS zoom。

## 限制与注意

- 断点续传取决于服务器能力和 `.aria2` 文件；失败重试沿用同一任务目录。
- 不支持迅雷专有协议、ed2k、网盘解析、Cookie/登录下载、自动解压或媒体转码；SFTP 需要核心和服务器兼容，第一版不提供账户密码输入。
- 默认上传限速 1024 KiB/s；下载不限速；并发 3；做种最长 60 分钟或分享率达到 1。Tracker 不保证无种资源可以下载。
- 为安全起见，直链下载的 `.torrent` / Metalink 不自动执行，需显式导入种子。
- 默认不内置公共 Tracker，不将私人种子信息主动发送给预设第三方。自行添加的 Tracker 可能接收任务信息，请勿给私有种子添加不可信 Tracker。
- 最多保留 1000 条任务，种子及链接元数据合计不超过 64 MiB。
- 所有网页操作仍依赖小米客户端的用户认证；本插件不提供独立公网管理页面。

- 设置页支持 aria2 版本检查、下载更新、SHA-256 与架构校验及启动失败回退。使用同一第三方静态构建渠道，不冒充官方 Linux 二进制；可勾选本机 Mihomo HTTP 代理 127.0.0.1:7890。切换时保存会话并短暂重启下载服务，任务和设置保留。插件重新安装会保留比内置版本更新的核心。
- 各插件样式和 DOM 操作限定在自己的根容器，不再修改电脑客户端的 html/body、字体或外部控件；电脑滚动与手机深色模式保持兼容。
- 删除按文件名和目录执行；文件清理失败仍移除任务记录并提示残留。原有失败记录不会自动清理，需手动再次删除。

### 1.0.5 删除清理

- 删除任务时清理其私有目录内自动生成的磁链种子与对应临时文件；手动导入的原始种子不受影响。
- 勾选同时删除文件后，按任务记录删除下载文件和续传文件，再自内向外删除任务创建的空文件夹。非空文件夹及用户选择的上级目录保留，不递归清空下载目录。
- 未勾选时保留下载内容，仅清理任务记录和自动生成的种子缓存；删除失败仍移除记录并提示残留。历史残留不会自动扫描或清理。

### 1.0.6 种子副本与文件列表

- 删除任务时同时清理 aria2 在该任务下载目录内生成的种子副本：RPC 上传按种子全文件 SHA-1 命名，磁链元数据按 infoHash 命名；兼容从旧任务保存的种子内容计算文件名。不关闭 aria2 元数据持久化，保留重启恢复能力。
- BT 文件选择改为按子目录分组，行内只显示文件名、大小与详情中的进度，支持全选和反选。详情每页 200 项，保留跨页选择；运行中的任务需先暂停再改选。
- 设置页新增「清理磁链缓存」。确认后只清理插件 `var/metadata` 内已无任务使用、命名符合规范的自动种子及对应临时文件；显示文件数、释放空间及保留/失败情况。
- 清理前核对任务库和 aria2 队列，保留解析中、下载中、暂停及历史任务的缓存；核心无法连接时拒绝清理。保留未知文件、符号链接、DHT 数据、续传文件及用户导入的原种子，不扫描下载目录。
- 已删除记录的旧任务无法可靠还原其下载目录与种子归属；旧版本留在下载目录内的种子不会被缓存按钮全盘扫描删除，需确认后手动处理。

### 1.0.7 详情边界修复

- 超长任务标题限制为两行，关闭按钮保持在弹窗内部；目录、错误说明支持长文本换行。
- 文件列表补齐网格与弹性布局的宽度约束，文件名在本列省略，大小和进度列不被挤出边界。兼容电脑小窗口和手机浅色/深色布局，不改动实际文件名或下载任务。
